# ReviewReview — Future Features Roadmap

> This document captures product ideas deferred from the initial release.
> Last updated: 2026-05-24

---

## Feature 1 — Reviewer Suggester

### Overview
Instead of evaluating a specific named reviewer, the user provides a paper and the AI automatically surveys the academic field to **propose and rank suitable reviewer candidates**.

### User Flow
1. User uploads a paper PDF (or pastes text / provides a DOI / arXiv ID).
2. The system identifies the paper's key topics, methods, and subfields.
3. The AI searches for researchers who are:
   - Active experts in those specific subfields
   - At an appropriate career stage (typically associate/full professor, senior researcher)
   - Not obvious conflicts of interest with the authors
4. Returns a ranked list of N candidates (e.g., 5–10), each with:
   - Name, institution, career stage
   - Expertise match score + explanation
   - Estimated COI level based on author graph proximity
   - Links to their Google Scholar / lab page

### Technical Approach
- Use Claude with web search to identify key figures in the field.
- Cross-reference against the author list for COI.
- Could eventually integrate with **OpenAlex** or **Semantic Scholar API** for structured author/citation data.
- Output format: ranked cards, exportable to CSV/JSON for journal submission systems.

### Open Questions
- How many candidates should be returned by default?
- Should the user be able to specify exclusion criteria (e.g., "not from institution X")?
- Should we support bulk input (multiple papers at once)?

## Feature 2 — AI or Human? (The Review Game)

### Overview
An interactive, game-like experience where visitors are shown a **real peer review excerpt** alongside an **AI-generated review paragraph** on a similar topic, and must decide which is which.

### User Flow
1. The app shows two paragraphs side by side (or stacked on mobile):
   - One excerpt from a real published review (sourced from open-access review data)
   - One AI-generated review comment on a similar paper/topic
2. The user clicks "This one is human" on their chosen paragraph.
3. The result is revealed with an explanation of the giveaways.
4. A running score / streak counter encourages continued play.
5. Optionally: leaderboard or shareable result card.

### Why This Is Useful
- Educates researchers and editors about AI-generated review patterns.
- Raises awareness of what to look for when screening reviews.
- Engaging marketing/educational tool for the platform.

### Data / Content Requirements
- Need a corpus of real peer review excerpts. Possible sources:
  - **PeerJ** open reviews
  - **eLife** published reviewer comments
  - **OpenReview.net** (NeurIPS, ICLR, etc.) — structured, machine-readable
- AI reviews: generated by Claude using the same paper abstract as context, instructed to produce a realistic-sounding but subtly AI-written review.

### Technical Approach
- Static content can be pre-generated and stored as JSON.
- For dynamic mode: fetch a random paper abstract → generate AI review on the fly.
- Track user answers in localStorage for streak/score; optionally sync to a backend for a global leaderboard.

### Design Notes
- Cards should feel like a real review interface (monospace font, academic aesthetic).
- Consider a "Confidence meter" — users rate how sure they are (1–5) before revealing.
- Mobile-first: most engagement will likely come from social media shares.

### Open Questions
- What is the licensing situation for using real review excerpts publicly?
- Should the game be accessible without an API key (using pre-generated content)?
- Do we want a backend leaderboard, or keep it fully client-side initially?

## Feature 3 — DOI / arXiv Input

### Overview
Instead of uploading a PDF, users can enter a **DOI** or **arXiv ID** and the app fetches the paper metadata automatically.

### Technical Approach
- For arXiv: use the arXiv API (`export.arxiv.org/api/query?id_list=...`) to fetch abstract and authors.
- For DOI: use CrossRef API (`api.crossref.org/works/{doi}`) to fetch metadata.
- Full text: for open-access papers, attempt to fetch PDF from Unpaywall API.

### Benefit
Dramatically lowers friction for users — no need to download a PDF.

## Feature 4 — Reviewer History / Session Persistence

### Overview
Store past evaluations locally so the user can revisit results without re-running the analysis.

### Technical Approach
- Save evaluation results to **IndexedDB** (via `idb` library) keyed by `(paper_title, reviewer_name, timestamp)`.
- Show a "Recent evaluations" panel in the sidebar or a history tab.
- Allow export to PDF or JSON.

---

## Feature 5 — Batch Mode

### Overview
Upload a CSV of (paper, reviewer_name) pairs and run evaluations in bulk, with a downloadable report.

### Use Case
Journal editors screening 10–20 proposed reviewers for a special issue at once.

---

## Feature 6 — Hosted Service

When ready to deploy publicly:

- **Backend**: FastAPI or Next.js API routes to proxy Anthropic calls (keep API key server-side).
- **Auth**: Simple email magic-link auth, or Google OAuth.
- **Pricing**: Freemium — N free evaluations per month, paid tier for bulk/history.
- **Privacy**: Option to flag that paper content is not stored or logged.
- **Compliance**: GDPR-friendly data handling, especially for EU users.
